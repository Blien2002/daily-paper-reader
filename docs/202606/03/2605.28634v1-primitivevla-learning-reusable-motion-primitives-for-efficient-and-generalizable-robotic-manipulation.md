## 摘要
视觉-语言-动作（VLA）模型为通用机器人策略提供了一种有前景的范式，但其适应性受到数据效率低下和泛化能力差的阻碍。我们认为这些瓶颈源于流行的直接指令到控制映射，这迫使模型记忆整体轨迹而非可重复使用的运动模式，即基元。我们提出PrimitiveVLA，这是一个将范式转向以基元为中心的拆解与组装框架。在共享的多模态规范表示（MCR）支持下，PrimitiveVLA统一了两个阶段：（1）微调阶段的拆解，使用自动化流水线将演示拆解为可重复使用的基元；（2）推理阶段的组装，采用基于VLM的规划器和由LLM生成的切换模块进行鲁棒的闭环执行。通过将任务拆解为可重复使用的基元，PrimitiveVLA使VLA模型能够学习不变的运动模式而非特定于任务的轨迹。大量实验表明，我们的框架提高了数据效率，并在未见过的和长时域任务中实现了卓越的零样本泛化。

## Abstract
Vision-Language-Action (VLA) models offer a promising paradigm for generalist robotic policies, yet their adaptation is hindered by data inefficiency and poor generalization. We argue that these bottlenecks stem from the prevailing Direct Instruction-to-Control Mapping, which forces models to memorize monolithic trajectories rather than reusable motion patterns, i.e., primitives. We propose PrimitiveVLA, a framework that shifts this paradigm toward a Primitive-Centric Disassemble & Assemble paradigm. Supported by a shared Multimodal Canonical Representation (MCR), PrimitiveVLA unifies two phases: (1) Fine-tuning-phase Disassembly, which uses an automated pipeline to disassemble demonstrations into reusable primitives; and (2) Inference-phase Assembly, which employs a VLM-based planner and an LLM-generated switch module for robust closed-loop execution. By disassembling tasks into reusable primitives, PrimitiveVLA enables VLA models to learn invariant motion patterns instead of task-specific trajectories. Extensive experiments show that our framework improves data efficiency and achieves superior zero-shot generalization across unseen and long-horizon tasks.

## 2. 方法论
### 核心思想
PrimitiveVLA 框架统一了微调阶段（基元拆解）和推理阶段（基元组装），通过 **多模态规范表示（Multimodal Canonical Representation, MCR）** 桥接两阶段。核心是将无限的任务集转化为有限基元库的策略组合。

### 关键技术细节
#### 2.1 基元库定义
- 定义了 **11 个可复用基元**，分为三类：
  - **空间运输**：Grasp（抓取）、Place（放置）、Lift（提升）、Move（移动）
  - **接触与交互**：Push（推）、Pull（拉）、Insert（插入）、Press（按压）
  - **定向**：Twist（扭转）、Tilt（倾斜）、Rotate（旋转）
- 每个基元有明确的运动学定义（见 Table 1）。

#### 2.2 微调阶段：基元拆解
- **Primitive Sequence Reasoning（基元序列推理）**：利用 VLM（如 Qwen3-VL）分析任务指令和演示视频帧，输出基元序列 S = [p1, p2, ..., pk]。生成的（指令, 序列）对存入拆解库 D，用于后续推理阶段的检索增强规划。
- **State-Based Boundary Segmentation（基于状态的边界分割）**：输入所有涉及的基元及其物理定义，让 LLM（如 DeepSeek-V3）生成 Python 代码 phi，该代码通过分析局部窗口中机器人状态变化（如夹爪宽度恒定且末端高度增加）来精确确定每个基元的终止时间。采用**规则驱动**而非 VLM 直接分割，保证稳定性和可解释性。
- **MCR 处理**：在微调前，所有拆解片段经 MCR 处理——原指令映射为统一的“规范基元指令”（如“grasp the object with green mask”），原始观测通过物体中心掩码（SAM + Cutie 跟踪）变为掩码观测。这**解耦了运动模式与任务上下文**，使同一基元在不同任务中共享训练信号。

#### 2.3 推理阶段：基元组装
- **Primitive Planner（基元规划器）**：对于新任务指令 l_test，从拆解库 D 中检索语义最相似的 3 个（指令, 序列）对作为上下文，连同指令、初始观测和基元定义输入 VLM，生成推理基元序列 S_plan。通过检索增强，防止 VLM 产生不合理序列。
- **Primitive Switch（基元切换器）**：LLM 基于任务相关基元集的物理定义和之前的分割代码，生成轻量级 Python 函数 f_switch。运行时维护一个滑动历史窗口 Ht（大小 W），当 f_switch 评估窗口内的统计趋势（如变化率）满足条件时，触发从当前基元到下一基元的切换。系统采用**双线程架构**：执行线程输出 VLA 动作，监控线程评估切换触发，实现闭环执行。

#### 2.4 多模态规范表示（MCR）
- **语义统一**：将同一基元的所有样本指令映射到一条规范指令（如“grasp the object with green mask”），约束语言空间，使模型关联策略与基元身份而非文本变化。
- **视觉兼容**：通过掩码观测 ˜oi = oi ⊗ Mi，其中 Mi 由 SAM 初始化并由 Cutie 跟踪。掩码携带任务特定上下文（操作对象和目标位置），同时保持 VLA 输入的统一格式，使模型能关注通用运动模式。

- **数据效率显著提升**：在 Libero-90 上，PrimitiveVLA 将 OpenVLA 成功率提升 9.2%，在 50% 训练数据下达到甚至超越全量基线的性能（例如 OpenVLA+Ours 用 50% 数据达到 80.30%，高于 OpenVLA 全量 78.70%）。

## 7. 优点
- **范式创新**：从“直接指令到控制”转向“基元拆解与组装”，抓住了 VLA 数据效率和泛化不足的根本原因，方法思路清晰。
- **自动化拆解流水线**：结合 VLM 语义推理和 LLM 规则代码，无需人工标注，可扩展至大规模数据集。
- **模块化设计**：各组件（拆解、规划、切换、MCR）可独立替换或改进，且与基础 VLA 架构无关（已验证 OpenVLA、OFT、π0.5）。
- **鲁棒性**：针对 VLM/LLM 噪声的分析表明，系统对常见错误（基元合并、掩码漂移）具有容忍性，不会严重降级。
- **推理开销低**：规划与代码生成在预执行阶段完成，运行时仅需轻量 Python 逻辑和高效物体跟踪（Cutie 在 768x768 下仅 30ms），几乎不影响原始 VLA 推理频率。

## 8. 不足与局限
- **基元集预定义**：目前基于 11 个运动学基元，对于高度灵巧的操作（如缝纫、精密装配）可能不足。作者承认这一点并计划未来探索无监督基元发现。
- **依赖 VLM/LLM 能力**：虽然实验表明少量噪声不影响结果，但拆解和规划阶段仍依赖 VLM 的领域知识，在极端新颖场景下可能生成不合理序列（尽管检索增强有所缓解）。
- **长时域执行依赖重置协议**：在 Libero-Long 评估中采用了重置策略（子任务后初始位姿归零），这在一定程度上减轻了域漂移；在完全连续的长时任务中，切换逻辑的鲁棒性还需进一步测试。
- **缺乏 end-to-end 可微规划**：当前规划器（VLM）与低级控制器（VLA+规则切换）分离，未来可探索端到端可微规划以优化协同。
- **实验偏差风险**：RLBench 部分任务（如 take_off_weighing_scales）成功率从标称 49.5% 提升到 56.5%，提升幅度相对较小（7%），可能受限于基元库对高自由度任务的覆盖；此外，真实世界实验仅在一个机器人平台上进行，需更多异构验证。
- **算力方面**：微调阶段需要 8 卡 GPU（L40S 或 A100），成本较高；虽然论文提及部署用 RTX 4090 可行，但大模型推理（VLM）仍需要高端 GPU。
