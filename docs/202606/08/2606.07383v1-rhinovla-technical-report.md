## 摘要
视觉-语言-动作（VLA）模型在机器人操作中展现出巨大潜力，但在边缘硬件上的实时部署仍具挑战。本文中，我们识别出VLM视觉和上下文令牌是部署延迟的主要来源：对于以GEMM为主的投影算子，当模型维度固定时，计算量随输入令牌数量线性增长。基于这一观察，我们提出RhinoVLA，一种与慧析R1边缘SoC协同设计的面向部署的VLA模型。RhinoVLA采用令牌高效的Qwen3-VL骨干网络和连续动作专家，在保留预训练多模态能力的同时，减少了VLM侧的令牌和计算负担。为支持跨机器人学习，RhinoVLA进一步引入统一接口，结合视图注册表、72维物理状态-动作槽空间和机器人实例LoRA，使异构机器人观测和动作模式能够在共享策略下对齐。在部署方面，RhinoVLA通过硬件感知编译、混合精度执行和并行视觉编码进行优化。实验表明，RhinoVLA在相似参数量下达到与π0.5相当的下游性能，同时在慧析R1上实现11.69 Hz的端到端推理，满足10 Hz实时闭环控制目标。该项目将开源，地址：https://github.com/HuixiAI/RhinoVLA。

## Abstract
Vision-Language-Action (VLA) models have shown strong potential for robotic manipulation, but real-time deployment on edge hardware remains challenging. In this work, we identify VLM visual and context tokens as a major source of deployment latency: for GEMM-dominated projection operators, computation grows linearly with the number of input tokens when model dimensions are fixed. Motivated by this observation, we propose RhinoVLA, a deployment-oriented VLA model co-designed with the Huixi R1 edge SoC. RhinoVLA adopts a token-efficient Qwen3-VL backbone and a continuous Action Expert, reducing the VLM-side token and computation burden while preserving pretrained multimodal capability. To support cross-robot learning, RhinoVLA further introduces a unified interface that combines View Registry, 72D physical state-action slot space, and robotinstance LoRA, allowing heterogeneous robot observations and action schemas to be aligned under a shared policy. On the deployment side, RhinoVLA is optimized through hardware-aware compilation, mixed-precision execution, and parallel visual encoding. Experiments show that RhinoVLA achieves downstream performance comparable to π0.5 at a similar parameter scale, while reaching 11.69 Hz end-to-end inference on Huixi R1, meeting the 10 Hz real-time closedloop control target. The project will be open-sourced at https://github.com/HuixiAI/RhinoVLA.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：视觉-语言-动作（VLA）模型在机器人操作中表现出色，但在边缘硬件（如Jetson Orin）上实时部署面临严重的延迟瓶颈。
- **关键发现**：VLM（视觉语言模型）的视觉和上下文token数量是延迟的主要来源。对于以GEMM为主的投影算子（如MLP中的gate_proj/up_proj/down_proj），当模型维度固定时，计算量（FLOPs）与输入token数量线性相关。以π0.5为例，其VLM骨干和动作专家占总推理时间的90%以上，其中MLP算子占VLM延迟的74.7%。
- **研究动机**：现有VLA模型（如π0.5、GR00T N1、RDT）在10Hz实时控制目标下已超过Jetson Orin的有效处理能力。因此，需要从算法和系统两方面协同优化，实现边缘端实时闭环控制。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
- **token高效骨干**：采用Qwen3-VL-2B作为VLM骨干，其在256×256图像下仅生成64个合并视觉token（对比PaliGemma的256个，减少4倍），直接降低后续MLP GEMM计算量。
- **统一跨机器人接口**：通过视图注册表、72维物理状态-动作槽空间、机器人实例LoRA，解决异构机器人数据（不同相机布局、动作定义、本体差异）的输入输出不一致问题。
- **部署优化**：在慧析R1 SoC上通过硬件感知编译、混合精度（W8A16）、并行视觉编码实现加速。

### 2.2 关键技术细节
1. **架构设计**：
   - VLM骨干：Qwen3-VL-2B（2.13B参数），冻结训练，仅训练VLM LoRA（r=64）。
   - 动作专家：0.40B参数，18层Transformer，条件于Qwen3-VL最后18层KV缓存、72D状态、遮罩、噪声动作块、流匹配时间、机器人实例索引，预测72D动作槽的流速度。
2. **统一接口**：
   - **视图注册表**：在图像前插入显式角色-模态标签（如`[head|rgb]`），解耦相机身份与数据集特定顺序。
   - **72D物理槽空间**：为每个维度分配固定物理意义（如D0-D6为第一臂关节弧度，D14-D15为平行夹爪闭合比等），配合二元状态/动作遮罩，标记有效维度。缺失维度不参与监督。
   - **机器人实例LoRA**：在动作专家每层FFN中插入实例LoRA，通过`instance_id`硬路由选择，学习本体特定残差。推理时可合并入基础权重，保持统一部署图。
3. **训练策略**：
   - **预训练**：使用混合机器人数据集（AgiBotWorld Beta & 2026，共2976.4小时G1、数百小时G2），冻结VLM，联合优化VLM LoRA、共享动作专家、实例LoRA。损失函数为遮蔽流匹配损失，仅计算有效动作槽，并加入残差正则化防止LoRA接管全部行为。
   - **后训练**：冻结VLM LoRA和共享动作专家，仅更新目标机器人的实例LoRA，使用少量真实任务数据微调。
4. **部署优化**：
   - 编译优化：算子级优化（FlashAttention适配R1 SPM）、图级融合（fused Attention+MLP）、运行时细粒度任务调度。
   - 混合精度：INT8权重+FP16激活（W8A16），定制GEMM核函数，融合加载、反量化、矩阵乘，达到1.69×加速（up_proj算子）。
   - 并行编码：三个相机视图批量处理，延迟从34.52ms降至24.31ms。
