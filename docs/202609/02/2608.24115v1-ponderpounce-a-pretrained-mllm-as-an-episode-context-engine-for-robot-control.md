## 摘要
多模态大语言模型（MLLM）能够整合长视觉历史、在部分可观测条件下进行推理，并从少量示例中推断行为。然而，视觉-语言-动作（VLA）模型通常仅继承预训练表示，而没有将这种上下文能力用作回合记忆。依赖记忆的策略通过专门构建的历史机制来弥补这一不足。PonderPounce 则复用 MLLM 的原生因果上下文作为机器人记忆。Ponder 是一个 System2 型 MLLM，在其原生因果上下文中累积回合观测、演示和先前的认知，并可为内部使用生成子目标文本和演示推理。Pounce 是一个 System1 型 VLA，直接接收当前观测、指令和本体感知；通过 Ponder-Pounce 接口，它异步接收最新的连续认知 token 及其年龄。两者端到端联合训练，无需专门构建的记忆模块或单独的桥接预训练。经过优化服务，认知刷新的 p50 延迟为 78ms，动作模型调用的 p50 延迟为 25ms，可支持 20Hz 的动作输出。在 RoboMME 上使用基础规模训练数据时，在相同 Pounce 架构和接口下，PonderPounce 使用 9B 达到 60.83%，使用 0.8B 达到 50.04%，而 FrameSamp+Modul 为 44.51%，当前观测 π_{0.5} 为 17.93%。在使用 9 倍数据时，其达到 75.54%，FrameSamp+Modul 为 57.88%。在 RoboCasa-DC 上，相同接口仅从动作监督中学习并达到 12.5%，而最强的已发表演示条件基线为 11.6%；当认知被替换为一个可学习的空状态时，性能下降到 8.6%。

## Abstract
Multimodal large language models (MLLMs) can integrate long visual histories, reason under partial observability, and infer behavior from a few examples. Yet vision-language-action (VLA) models generally inherit pretrained representations without using this contextual capacity as episode memory. Memory-dependent policies address this gap through purpose-built history mechanisms. PonderPounce instead reuses an MLLM's native causal context as robot memory. Ponder, a System2 MLLM, accumulates episode observations, demonstrations, and prior cognition in its native causal context and can generate subgoal text and demonstration reasoning for internal use. Pounce, a System1 VLA, receives the current observation, instruction, and proprioception directly; through the Ponder--Pounce interface, it asynchronously receives only the newest continuous cognition token and its age. Both are jointly trained end to end without a purpose-built memory module or separate bridge pretraining. Optimized serving achieves p50 latencies of 78ms for cognition refresh and 25ms for action-model invocation, supporting 20Hz action playback. On RoboMME with base-scale training data, PonderPounce reaches 60.83% with 9B and 50.04% with 0.8B under the same Pounce architecture and interface, versus 44.51% for FrameSamp+Modul and 17.93% for the current-observation π_{0.5}. With 9x data, it reaches 75.54% versus 57.88% for FrameSamp+Modul. On RoboCasa-DC, the same interface learns from action supervision alone and reaches 12.5% versus 11.6% for the strongest published demonstration-conditioned baseline, falling to 8.6% when cognition is replaced by a learned null state.

## 1. 论文的核心问题与整体含义

- **研究动机**：机器人操控常常依赖当前观测中缺失的证据，例如被遮挡的物体、之前发生的事件、指代对象的身份或演示流程。多模态大语言模型（MLLM）能够整合长视觉历史并进行上下文推理，但现有视觉-语言-动作（VLA）模型通常只继承预训练视觉/语言表示，**没有将这种上下文能力实际用作“回合记忆”（episode memory）**。
- **现有缺口的本质**：记忆依赖型策略通常需要**专门设计的历史机制**，如采样、存储、检索、压缩、交叉注意力或中间规划图等。这些机制需要为机器人轨迹单独设计或学习，增加了架构复杂性和工程成本。
- **本文核心思想**：**直接复用预训练 MLLM 的原生因果上下文作为机器人记忆**，而不是额外构建一个专用记忆模块。通过将一个 System 2 型 MLLM（Ponder）与一个 System 1 型 VLA（Pounce）异步连接，把积累的上下文压缩为一个连续的“认知 token”传递给动作控制器。
- **整体含义**：证明了“预训练 MLLM 上下文”可以作为一种**可扩展、通用但并非万能**的记忆基底；System 2 的容量可以独立扩展，而不必改变快速动作路径的控制器架构。

## 2. 论文提出的方法论

### 2.1 双系统架构

- **Ponder（System 2）**：
  - 使用预训练 MLLM（主实验为 Qwen3.5-9B）。
  - 维护**仅追加（append-only）的因果上下文**，其中包含：任务指令、可选演示、历史观测、内部生成的子目标文本与演示推理、以及之前的认知载体状态。
  - 每次查询时，Ponder 预测一个**转移 token** \(T_t \in \{T_{\text{Yes}}, T_{\text{No}}\}\)：
    - 若 \(T_t = T_{\text{Yes}}\)，则先内部生成子目标文本 \(S_t\)（在演示任务的首次执行转移时还会生成演示推理 \(DR\)）。
    - 若 \(T_t = T_{\text{No}}\)，则直接在观测后放置认知载体位置。
  - 载体位置的最终隐藏状态构成认知 \(C_t \in \mathbb{R}^{K \times H}\)，**不进行解码或池化**。每条查询都会产生新鲜的认知，但 \(DR\) 和 \(S_t\) 保持为 System 2 内部信息。

- **Pounce（System 1）**：
  - 使用预训练 VLA 动作模型（RoboMME 上为 π0.5-3.6B，RoboCasa-DC 上为 GR00T N1.5-3B）。
  - 输入：指令、当前观测、本体感知，以及由**最新就绪认知**和其**正弦编码年龄**组成的前缀。
  - 若没有就绪认知，则使用可学习的空认知 \(C_\emptyset\) 并将年龄设为 0。
  - 动作头预测动作块 \(A_{1:h}\)，以 20 Hz 回放。

### 2.2 端到端联合训练与损失

- 损失函数：
  \[
  L = w_1 L_{\text{fm}} + w_2 L_{\text{ground}}
  \]
  其中 \(L_{\text{fm}}\) 是动作流匹配 MSE，\(L_{\text{ground}}\) 是 token 交叉熵，监督目标包括：
  - 转移 token \(T^*_t\)；
  - 在标注转移点上的子目标文本 \(S_t\)；
  - 演示片段首次执行转移时的演示推理 \(DR\)。
- 训练时对标注目标进行**教师强制**；推理时 Ponder 自行预测 \(T_t\)，并仅在 \(T_t = T_{\text{Yes}}\) 时生成文本。
- 动作梯度通过 \(C_t\) 反向传播到 Ponder，接地梯度通过 LM 头反向传播。作者将进入 Ponder 的动作梯度缩放为 0.5，以平衡两条路径。

### 2.3 异步调度与推理优化

- 两个模型时钟解耦：Ponder 查询观测时间 \(\tau^{(2)}_t\)，Pounce 调用时间 \(\tau^{(1)}_j\)；调度器选择最新已就绪认知：
  \[
  \text{ref}(j) = \max \left\{ t : \tau^{(2)}_t + d_t \le \tau^{(1)}_j \right\}
  \]
  其中 \(d_t\) 是计算延迟。若集合为空则使用空认知。
- 训练时在 RoboMME 上对 Pounce 采样约 100 ms、Ponder 约 1 s 的 log-normal 间隔，并加入 300 ms 计算延迟；评估时固定 1 Hz 模型时钟和 300 ms 延迟。
- 推理优化：使用**仅追加的 StaticCache 会话**只编码新 token；认知-only fire p50 为 77.9 ms，45-token 子目标 fire p50 为 820.2 ms；Pounce 使用融合 Triton 内核从 142 ms 降至 25 ms。

## 6. 主要结论与发现

- **PonderPounce 在 RoboMME 上显著优于专用记忆基线**：1× 数据下 60.83% vs FrameSamp+Modul 44.51%；9× 数据下 75.54% vs 57.88%。尤其在 Permanence 和 Reference 任务上领先，但在 Imitation 上仍弱于 FrameSamp+Modul。
- **原生 MLLM 上下文具有可扩展性**：在相同 Pounce 架构和接口下，9B 预训练 Ponder 比 0.8B 高出 10.79 个百分点（60.83% vs 50.04%），说明更大的 System 2 容量可以改善控制，且无需改变快速控制器。
- **认知通道对控制有因果贡献**：在 RoboCasa-DC 上，禁用认知（替换为可学习空状态）使成功率从 12.5% 降至 8.6%；在 RoboMME 上，去除 LM-head 接地使成功率从 60.83% 降至 27.96%。
- **连续认知接口与离散子目标文本接口竞争力相当**：连续认知 60.83% vs 子目标文本参考 59.96%，差距小于运行间波动，表明连续认知并非明显更优，但具有竞争力。
- **及时刷新对性能至关重要**：同一 checkpoint 若只在预测转移时更新认知，成功率跌至 1.83%；但作者指出这并不排除专门为稀疏传输训练的策略的有效性。
- **推理优化可实现实时性**：认知刷新 p50 78 ms，动作模型调用 p50 25 ms，支持 20 Hz 动作回放。

## 7. 优点

- **设计简洁且通用**：没有引入专用记忆存储、检索路径或压缩器，直接复用 MLLM 的原生因果上下文，降低了架构复杂性。
- **独立可扩展性**：System 2 的容量可以改变（如 9B→0.8B），而 System 1 控制器和接口保持不变，使记忆容量成为独立设计轴。
- **异步解耦时钟**：将慢速上下文推理从快速动作路径中分离，保证实时控制的同时允许 System 2 离线扩展。
- **端到端联合训练**：无需单独桥接预训练或子系统特定预训练，训练流程更简单。
- **实验相对扎实**：包含两个基准、两种数据规模、多个消融、延迟剖析和模型规模/初始化分析；在 RoboMME 上报告了三次运行均值和任务级细分。
- **诚实的局限性讨论**：作者明确指出监督差异、诊断局限性、随机初始化未收敛等问题，没有过度声称。

## 8. 不足与局限

- **监督与基线的公平性**：PonderPounce 使用了模拟器提供的转移门/子目标/演示推理标注，而许多基线没有同等监督，因此优势可能部分来自额外信息，而非架构本身。
- **实验范围有限**：仅覆盖两个模拟基准；RoboCasa-DC 绝对成功率很低，且只有五个 held-out 任务，不能证明广泛的跨具身泛化。
- **认知表示仍不透明**：虽然消融显示认知对控制有贡献，但认知具体编码了什么、Pounce 如何使用它仍是开放的；缺乏表示探针或更深层的可解释性分析。
- **稀疏传输未充分验证**：held-state 干预和 teacher-forced 陈旧性诊断都不能替代专门为稀疏认知传输训练的策略的闭环评估。
- **计算成本较高**：9B Ponder 加上 3~3.6B Pounce 的联合训练和推理开销大；附录中的延迟测量是 batch-1 调用，未涉及并发吞吐。
- **上下文长度受限**：append-only 上下文限制在 16K token，可能不足以应对极长时序任务。
- **随机初始化实验不收敛**：无法严格分离预训练与随机初始化的因果贡献。
- **RoboCasa-DC 无基线的方差信息**：已发表基线没有不确定性，难以判断差异的统计显著性。
