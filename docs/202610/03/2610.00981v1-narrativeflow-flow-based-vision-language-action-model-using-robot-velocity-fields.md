## 摘要
我们专注于语言条件下的基于流的操控，其中机器人流（机器人速度场）作为与机器人本体无关、以运动为中心的表示，用于利用从多个机器人平台收集的数据。该任务至关重要，因为语言条件下的操控对于实用机器人系统必不可少，然而扩展机器人基础模型仍受到具体机器人本体数据收集劳动密集的限制。现有方法要么用稀疏关键点位移粗略近似机器人流，要么无法处理语言条件下的操控。为解决这一局限，我们提出了 NarrativeFlow，它采用以语言为条件的流匹配公式，将机器人流建模为连续速度场。因此，NarrativeFlow 生成的机器人流在物理上与真实世界操控一致。为验证 NarrativeFlow，我们在语言条件操控的标准数据集上进行了实验。实验结果表明，NarrativeFlow 在标准评估指标上优于代表性基线方法。此外，通过真实世界实验，我们表明 NarrativeFlow 在多个操控任务中取得了比基线方法更高的成功率。项目页面见 https://shota0520.github.io/NarrativeFlow-project-page/

## Abstract
We focus on language-conditioned flow-based manipulation, where robot flows (robot velocity fields) serve as embodiment-agnostic, motion-centric representations for leveraging data collected from multiple robot platforms. This task is crucial because language-conditioned manipulation is essential for practical robotic systems, yet scaling robot foundation models remains limited by the labor-intensive collection of embodiment-specific data. Existing methods either coarsely approximate robot flows with sparse keypoint displacements, or cannot handle language-conditioned manipulation. To address this limitation, we propose NarrativeFlow, which models robot flows as continuous velocity fields using a flow-matching formulation conditioned on language. Accordingly, NarrativeFlow generates robot flows that are physically consistent with real-world manipulation. To validate NarrativeFlow, we have conducted experiments on standard datasets for language-conditioned manipulation. The experimental results show that NarrativeFlow outperforms representative baseline methods on standard evaluation metrics. Furthermore, through real-world experiments, we show that NarrativeFlow achieves higher success rates than baseline methods across multiple manipulation tasks. The project page is available at https://shota0520.github.io/NarrativeFlow-project-page/

# NarrativeFlow 论文总结

## 1. 论文的核心问题与整体含义

- **研究背景**：语言条件下的机器人操控（language-conditioned manipulation）是实用机器人系统的关键能力，但扩展机器人基础模型受限于需要大量具体机器人本体（embodiment）数据，数据采集成本高、劳动密集。
- **核心问题**：如何利用跨机器人平台的数据，学习一种既与机器人本体无关、又能理解自然语言指令的操控表示。
- **本论文定位**：专注于**语言条件下基于流的操控（language-conditioned flow-based manipulation）**，即根据初始图像和语言指令生成“机器人流”（robot flow / robot velocity field，机器人速度场），再让机器人根据该流执行操作。
- **现有方法不足**：
  - 许多方法（如 FLIP、Im2Flow2Act）将机器人流近似为稀疏关键点的位移，忽略机器人运动作为连续时间演化物理过程的本质。
  - 这些方法通常只用主流程生成损失训练，缺少对任务相关语义的显式监督，容易受背景、光照等无关视觉细节干扰。
  - Flow as Flow 虽能建模稠密速度场，但不支持语言条件，只能用于目标条件设置。
- **整体含义**：提出一种将机器人流建模为**连续速度场**、并用**流匹配（flow matching）**框架在语言条件下生成的方法，使生成的机器人流在物理上更符合真实操控，同时通过辅助损失增强任务相关语义理解。

## 2. 方法论

### 2.1 总体架构

NarrativeFlow 由两个核心模块组成：

- **视觉语言融合编码器（Vision-Language Fusion Encoder）**：输入语言指令 ℓ 和初始图像 I₀，输出两个专门用于不同下游路径的联合表示。
- **Flow-as-Flow 模块**：在语言条件的引导下，用流匹配方式生成连续速度场，并积分得到机器人流点坐标。

### 2.2 输入编码

- 语言指令 ℓ：使用 **Qwen3-Embedding-0.6B** 提取语言嵌入 \( z_{\text{lang}} \)。
- 初始图像 I₀：使用 **DINOv3-ViT-B/16** 提取视觉嵌入 \( z_{\text{img}} \)。
- 图像额外加入机器人末端执行器掩码的 alpha 通道（由微调后的 Robot-SAM 生成）。

### 2.3 视觉语言融合编码器与子任务 token

- 传统单 token（如 [CLS]）同时用于条件生成模块和辅助损失，会导致学习信号相互纠缠。
- 本文引入**两个子任务 token（subtask tokens）**，分别用于：
  1. \( z^{(1)}_{st} \)：条件 Flow-as-Flow 模块，生成机器人流。
  2. \( z^{(2)}_{st} \)：计算 Narrative Delta 损失，学习任务相关场景变化表示。
- 两个 token 与视觉、语言嵌入拼接后，经过 Transformer 编码器，分别投影得到两个专门的读出表示。

### 2.4 Narrative Delta 损失（辅助损失）

- **动机**：仅用流生成损失无法显式约束中间表示，可能把任务相关场景变化与任务无关视觉细节纠缠在一起。
- **构建过程**：
  1. 给定初始图像 I₀ 和目标图像 G，用 MLLM（实验中为 Qwen3.5-9B）离线生成 \( N_c \) 条描述同一任务相关场景变化但不重复的文本（例如机器人姿态变化、物体位移等，忽略背景和光照）。
  2. 用 Qwen3-Embedding-0.6B 嵌入这些文本，得到目标叙事表示 \( \{ z^{(i)}_{ND} \}_{i=1}^{N_c} \)。
  3. 计算 \( z^{(2)}_{st} \) 与多个目标叙事表示之间的平均余弦相似度损失：

\[
\mathcal{L}_{ND} = \frac{1}{N_c} \sum_{i=1}^{N_c} \left[ 1 - \text{cossim}\left( z^{(2)}_{st}, z^{(i)}_{ND} \right) \right]
\]

- 该损失只在训练时使用，推理时不需要目标图像 G。

### 2.5 Flow-as-Flow 模块与流匹配

- 将机器人流视为在初始图像 I₀ 上初始化的 \( N \) 个点（如 10×10）随时间的运动轨迹。
- 给定地面真值点坐标 \( \Xi_t \) 和速度 \( \dot{\Xi}_t \)，构造目标速度场：

\[
v(\Xi_t, X, t) = \dot{\Xi}_t - k (X - \Xi_t)
\]

其中 \( X \sim \mathcal{N}(\Xi_t, \sigma_0^2 e^{-2kt} I) \)，\( k \) 为稳定系数，\( \sigma_0 \) 为小常数。

- 速度场预测器 \( v_\theta \) 基于 **Diffusion Transformer（DiT）** 架构，每个 DiT 块通过 adaLN-Zero 调制，条件向量由 \( z^{(1)}_{st} \)、I₀ 编码和时间 t 编码相加构成。
- 推理时，通过积分速度场得到点坐标：

\[
X_t = X_0 + \int_0^t v_\theta\left( X_\tau, \tau \mid I_0, z^{(1)}_{st}, X_{<\tau} \right) d\tau
\]

- 总损失为：

\[
\mathcal{L} = \mathcal{L}_{FaF} + \lambda \mathcal{L}_{ND}
\]

其中 \( \mathcal{L}_{FaF} \) 是条件流匹配损失，对预测速度场与目标速度场之间的差异做回归。

### 2.6 训练细节

- 模型约 487M 可训练参数。
- 训练 300,000 步，batch size 128，优化器 AdamW，学习率 \( 1 \times 10^{-4} \)，余弦衰减，warmup 9000 步，weight decay 0.01，EMA decay 0.9999。
- \( \lambda \) 在前 30k 步为 0.1，之后为 \( 1 \times 10^{-5} \)。
- 超参数：\( T = 8 \)，\( N = 10 \times 10 \)，\( k = 1 \)，\( \sigma_0 = 0.05 \)，\( N_c = 5 \)。

## 3. 实验设计

### 3.1 数据集

- **Fractal**：Google Robot 平台采集，87,212 个样本；训练/验证/测试分别为 84,212 / 1,000 / 2,000。
- **Bridge V2**：WidowX 平台采集，60,064 个样本；训练/验证/测试分别为 57,064 / 1,000 / 2,000。
- 两个数据集来自不同真实机器人平台，在运动模式、背景、视角等方面存在差异，适合评估跨本体泛化能力。
- 数据预处理：
  - 图像统一 resize 到 256×256。
  - I₀ 为每个 episode 第一帧；成功 episode 中 G 为判定成功的帧，失败 episode 中 G 为最后一帧。

- 评估范围限制在末端执行器区域，避免静止背景主导指标。

### 3.3 基线方法

- **FLIP**：语言条件机器人流生成基线。
- **Im2Flow2Act**：代表性语言条件流生成方法，采用稀疏关键点位移。
- 两者使用与 NarrativeFlow 相同的数据集训练。

### 3.4 真实世界实验

## 6. 主要结论与发现

- NarrativeFlow 在 Fractal 和 Bridge V2 两个标准数据集上，全部指标均优于 FLIP 和 Im2Flow2Act；例如 Bridge V2 上 ADE 从最佳基线 50.73 降至 30.59，Fractal 上从 37.14 降至 21.68。
- 真实世界实验中，NarrativeFlow 平均成功率 55%，高于最强基线 Im2Flow2Act 的 42%；与 oracle 的成功率差距从 21 个百分点缩小到 8 个百分点，说明生成的机器人流更接近真实运动。
- 消融表明：
  - 两个子任务 token 能减少不同学习信号干扰，单独共享 token 或不用 token 会降低性能。
  - Narrative Delta 损失提供任务相关场景变化监督，移除该损失会使 ADE 变差。
  - 连续速度场建模优于稀疏关键点位移建模。
  - 使用更大 MLLM 生成 caption 能带来更好辅助监督。
- 误差分析显示，主要失败原因是多模态语言理解错误（如选错目标物体），其次是中间轨迹偏差、注释错误等。

## 7. 优点

- **连续速度场建模**：用流匹配将机器人流表示为概率速度场，比稀疏关键点位移更符合机器人操控的物理过程，能捕捉连续运动。
- **语言条件扩展**：将原本仅支持目标条件的 Flow as Flow 扩展到语言条件设置，使方法更实用。
- **Narrative Delta 损失**：利用初始-目标图像对离线生成的多视角文本描述，显式对齐中间表示与任务相关场景变化，减少对背景、光照等无关因素的敏感性；推理时无需目标图像。
- **子任务 token 设计**：分离条件生成和辅助损失的学习信号，避免单 token 的纠缠问题，提升表示质量。
- **实验充分**：包含标准数据集、真实世界、消融、补充实验和误差分析，验证较为全面。
- **跨本体表示**：机器人流作为本体无关表示，有利于利用多平台数据，减少对特定本体数据采集的依赖。

## 8. 不足与局限

- **2D 表示限制**：机器人流在图像平面内定义，无法处理深度方向的显著运动（例如从书架向相机方向拉书），这是论文在结论中明确指出的未来方向。
- **数据集覆盖有限**：仅使用 Fractal 和 Bridge V2 两个标准数据集；未在更大规模或更多样化的数据集（如 DROID、AgiBot World、RoboMIND 等）上评估跨本体泛化能力。
- **真实世界任务成功率有限**：部分任务（如杯子堆叠）最高仅 20
