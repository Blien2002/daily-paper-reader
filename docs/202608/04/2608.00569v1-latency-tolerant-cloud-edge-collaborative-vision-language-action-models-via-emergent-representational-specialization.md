## 摘要
在移动机器人上部署十亿参数的视觉-语言-动作（VLA）策略引发了一个系统冲突：语义推理受益于云端GPU，而闭环控制必须在本地响应，尽管存在网络延迟和抖动。现有的分层和异步策略提高了吞吐量，但其慢路径表示仍可能过时到达，或需要显式调度和延迟提示。我们引入了CloudEdgeVLA，一种将时间错位视为表示学习问题的云边策略。云端VLA将延迟观测编码为缓慢变化的任务特征，而轻量级边缘头将最新的可用云特征与当前本地视觉相结合。在训练过程中，当前帧和随机延迟帧在新鲜路径和过时路径中与相同的当前动作目标配对。这一目标鼓励云表示保留任务级信息，而边缘路径提供状态敏感修正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口下保持了63.8–78.0%的成功率，而VLASH最高仅为6.4%，所评估的单路径基线最高仅为3.0%。通过从控制回路中移除阻塞同步，该设计为可扩展的VLA部署提供了一条实用途径，其中云模型可以增长，而边缘计算保持轻量级和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

# 基于涌现表示特化的延迟容忍云边协同视觉-语言-动作模型（CloudEdgeVLA）

## 1. 核心问题与整体含义

**研究动机与背景**：视觉-语言-动作（VLA）模型在机器人操控领域展现出广阔前景，但其动辄数十亿参数的规模形成了部署瓶颈——功率与重量受限的机器人难以在本地承载如此庞大的计算需求。云机器人技术将昂贵感知与规划迁移至远程服务器，但引入了通信延迟、抖动与丢包问题。核心矛盾在于：云端返回的特征描述的是"图像采集时刻"的场景，而非"动作执行时刻"的场景。若阻塞等待新特征到达，控制频率骤降；若使用最新到达的特征，则产生时间错位。

**现有方案的不足**：
- 动作分块（action chunking）假设执行期间环境静止，延迟会累积误差；
- 同步快慢双系统要求固定频率比和有界延迟，不适用于网络化部署；
- 现有异步策略（如VLASH）在中等延迟下表现尚可，但在长延迟（40步均匀延迟窗口）下成功率几乎归零。

**核心洞见**：时间错位应被视为表征学习问题，而非仅靠推理调度或显式延迟提示解决。论文据此提出 **CloudEdgeVLA**——将云端VLA编码为缓慢变化的任务特征，边缘头融合最新云端特征与当前本地视觉，不依赖任何时钟对齐或阻塞同步。

## 2. 方法论

### 2.1 系统架构（三分量，时间不对称）

**云端VLA骨干 `fθ`（System 2，延迟不敏感）**：大规模视觉-语言模型，在预训练VLM基础上用LoRA适配，处理观测与指令，输出规划特征 `h = fθ(o, ℓ) ∈ R^{L×D}`。训练目标使其编码"做什么"（任务目标、操作策略、物体语义）而非"何时做"。

**边缘视觉编码器 `vψ`（System 1 感知，延迟敏感）**：轻量级视觉编码器（SigLIP-Base，冻结），本地实时提取当前观测特征 `zt = vψ(ot)`，无延迟，捕获即时环境状态。

**边缘动作头 `gϕ`（System 1 控制，延迟敏感）**：可学习模块，融合（可能过时的）云端规划特征与实时边缘视觉特征，预测连续动作 `ât = gϕ(h_{t-k}, zt) ∈ R^{T×A}`。先对规划特征做均值池化，投影视觉特征至同一潜在空间，拼接后经残差MLP输出动作块。

### 2.2 配对帧双路径训练（Paired-Frame Dual-Path Training）

**配对帧提取**：从演示轨迹中取W个连续帧窗口，构造：
- 当前帧：`ot`
- 延迟帧：`ot-d`，其中 `d ~ Uniform(1, W-1)`

**双前向传播**：两帧均通过云端骨干，得到新鲜特征 `h_fresh` 和过时特征 `h_stale`（均含梯度，不分离）。

**视觉增强动作预测**：两组规划特征与同一实时视觉特征 `zt = vψ(ot)` 融合，产生 `â_fresh` 和 `â_stale`。

**双路径损失**：
```
L = (1-λ)·‖â_fresh - at‖₁ + λ·‖â_stale - at‖₁
```
其中 `L_fresh` 训练同步操作的头部，`L_stale` 训练头部用实时视觉补偿过时特征。采用课程学习：在前 `n_warmup` 步将 λ 从0线性增至 `λ_max`。

### 2.3 涌现表示特化的机理

过时路径用 `t-d` 时刻的云输入预测 `t` 时刻的动作。对于随机延迟 d，仅与 `ot-d` 瞬时状态绑定的特征不可靠，但任务身份、目标、粗略进度等更稳定——这促使（但不保证）云特征对时间位移不变；当前边缘特征 `zt` 保留状态敏感信息。形成互补性：云特征随时间稳定 + 边缘感知动作头衰减残余不匹配。

### 2.4 部署协议（完全异步）
边缘捕获观测 → 异步发送云端 → 云端返回（可能过时）特征 → 边缘实时提取视觉特征 → 融合生成动作 → 执行。机器人**永不阻塞**等待云端，始终使用最新收到的特征。

## 6. 主要结论与发现

**主实验核心结果**：
- dmax=40时，CloudEdgeVLA保持63.8–78.0%成功率，VLASH最高仅6.4%，单路径基线最高3.0%。
- 四套件平均延迟AUC达90.8%（VLASH仅32.4%），dmax=40时保留同步成功率76.5%（VLASH仅1.8%）。

**消融关键发现**：
- 加入冻结SigLIP-Base使成功率从31.6%提升至95.1%（+63.5pp），说明实时视觉落地是关键；
- 更大编码器（SigLIP-SO400M）仅增加0.7pp，支持轻量级Base用于边缘部署；

## 7. 优点与亮点

1. **问题表述新颖**：将延迟鲁棒性定义为表征学习属性而非调度问题，概念上清晰且有启发性。
2. **系统-2/系统-1类比恰当**：不是修辞性比喻，而是具体分解为"云端任务特征 + 边缘即时落地"，架构与类比严格对应。
3. **简单有效的训练策略**：配对帧双路径训练无需延迟元数据、无需不变性损失，以弱监督方式诱导表征特化，优雅简洁。
4. **严格的不阻塞部署协议**：消除同步屏障，使云端模型可任意扩展而边缘保持轻量响应。
5. **实验严谨度高**：多种机制诊断（骨干-头部拆分、反事实独立年龄、动作块分解、逐任务分析）深入揭示了方法实际运作的机理。
6. **科学诚实**：主动报告边缘校正极小的负结果，对机制主张设限，不夸大贡献。
7. **延迟弹性**：扩展到训练窗口外的延迟（dmax>20），仍保持良好性能，超越训练分布泛化。

## 8. 不足与局限

1. **实验覆盖有限**：仅在LIBERO仿真验证，真实世界仅一个简单拾放任务和一个平台，未覆盖复杂操作、密集接触或非结构化环境。
2. **真机统计功效弱**：10次/单元格的试点数据，作者仅视为描述性证据，差异缺乏统计检验支持。
3. **机理归因出现矛盾**：主文强调"边缘路径提供状态敏感修正"，但反事实审计表明120k检查点的边缘直接修复作用仅0.03%，说明机制主张与实际测量存在张力。
4. **无界延迟不适用**：延迟容忍仅在测试范围内有效；长时间断连会连任务级上下文也失效。
5. **训练成本**：配对帧需两次骨干前向传播，增加训练开销，文中未量化此成本。
6. **传感器模态限制**：冻结的RGB编码器无法利用深度、力觉、触觉等关键模态信息。
7. **真实网络条件未测**：仅使用均匀或固定偏移延迟，未测试带宽受限、丢包、突发抖动等实际网络特征；延迟以环境步数计量，墙钟时长取决于控制频率，结果不具备硬件无关的普适性。
8. **硬件泛化未验证**：真机边缘设备为工作站级（RTX 5080），未证明嵌入式级硬件的可行性。
