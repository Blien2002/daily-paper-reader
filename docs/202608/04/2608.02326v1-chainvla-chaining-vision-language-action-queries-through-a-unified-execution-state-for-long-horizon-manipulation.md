## 摘要
人类执行长时程操控时，会保留先前动作所建立的状态认知，并持续调整当前进行的动作。相比之下，动作分块的视觉-语言-动作（VLA）策略在每次查询时都会根据当前输入重复规划。现有方法要么通过记忆保留长期任务证据，要么通过动作复用与集成保留短期运动，导致跨查询的交接不完整。我们提出了ChainVLA，一个12亿参数的VLA策略，通过一个联合且可修订的执行状态来链接连续的查询。进度上下文（Progress Context）将循环工作状态与稀疏事件记忆相结合，以携带从观测中得到的任务进度；而运动尾部（Motion Tail）则将先前预测中未执行的延续部分输入到状态构建和动作生成中。这两个组件共同调节一个解码器，该解码器在最新观测下重新生成每个动作序列，使得携带的状态能够引导下一次预测而不固定它。ChainVLA在RMBench上达到了62.8%的平均成功率，在四个LIBERO套件上达到了98.8%，而去除Motion Tail或Progress Context后，RMBench的成功率分别降至11.2%和3.0%。这些不对称的消融结果与运动连续性有助于保留观察流（任务进度从中推断）的结论一致。

## Abstract
Humans perform long-horizon manipulation by retaining knowledge of what earlier actions have established while continuously adapting the motion underway. By contrast, action-chunked vision-language-action (VLA) policies repeatedly replan from the current input at each query. Existing methods preserve either long-term task evidence through memory or short-term motion through action reuse and ensembling, leaving the cross-query handoff incomplete. We introduce ChainVLA, a 1.2B-parameter VLA policy that chains successive queries through a joint and revisable execution state. Progress Context combines a recurrent Working State with sparse event memory to carry observation-derived task progress, while Motion Tail feeds the preceding prediction's unexecuted continuation into state construction and action generation. Together, the two components condition a decoder that regenerates each action horizon under the latest observation, allowing the carried state to guide the next prediction without fixing it. ChainVLA reaches 62.8% average success on RMBench and 98.8% across four LIBERO suites, while removing Motion Tail or Progress Context reduces RMBench success to 11.2% and 3.0%, respectively. These asymmetric ablations are consistent with motion continuity helping preserve the observation stream from which task progress is inferred.

# ChainVLA 论文详细总结

## 1. 论文的核心问题与整体含义

**研究动机与背景：**
- 长时程操控（long-horizon manipulation）中，人类会保留先前动作已建立的任务进展信息，同时持续调整当前运动。这对应两个需求：**任务进展（task progress）** 与 **运动延续（motion continuation）**。
- 然而，现行动作分块（action-chunked）VLA 策略采用"重复滚动时域"（receding-horizon）的执行方式：每次查询预测一段有限动作序列、执行严格前缀、再重新规划；每次规划都是基于当前观测/本体感觉/指令重新生成，**缺少跨查询的显式交接**。
- 现有两类补救方案各偏一端：
  - **记忆增强类**（MemoryVLA、Keyframe Chaining、EventVLA 等）保留长期任务证据，但丢掉了上一次预测中未执行的延续动作；
  - **运动延续类**（Temporal Ensemble、实时执行、原生延续等）保留短期运动平滑，却无法追溯很久之前、已离开视野的任务证据。
- 由此引出核心问题：**VLA 策略如何跨查询同时衔接任务进展与运动延续，同时又保持对新观测的响应性？**

**整体含义：** 论文认为跨查询交接需要"联合可修订执行状态"，而非单纯记忆或单纯动作平滑。

## 2. 方法论

**核心思想：**
- 提出 ChainVLA——一个 **12亿参数（1.2B）** 的 VLA 策略，通过统一的执行状态 `sk = (gk, uk)` 将连续查询链式连接起来：
  - **Progress Context `gk`（回顾性）**：携带观测衍生的任务进展 = 循环工作状态（Working State）与稀疏事件记忆检索结果融合。
  - **Motion Tail `uk`（前瞻性）**：上一查询预测出但未执行的后缀（unexecuted suffix），直接跨越查询边界。
- 状态是可修订（revisable）的先验而非固定计划：解码器在最新观测下重新生成完整动作序列的每个位置。

**关键技术细节：**

1. **问题形式化**：考虑严格前缀滚动时域（`1 ≤ hexec < H`），查询 k 输入 `xk=(ok, rk, ℓ)`，预测 `Ak=(ak,1,...,ak,H)`，执行前 `hexec` 个动作。决策不充分条件：相同当前输入对应不同历史时，最优执行前缀集合不相交。
2. **查询转移公式**：
   ```
   (Ak, Wk, Ck+1) = Fθ(xk, Dk, Wk−1, Ck, uk)
   uk+1 = Tail(Ak) = (ak,hexec+1, ..., ak,H)
   ```
   训练与部署共享该有序转移；训练时携带的后缀会做 detach。
3. **循环工作状态（Working State）**：由当前直播令牌（live tokens `Lk`）和有限缓存 `Bk` 组成；8 个学习工作查询（learned working queries）通过 CrossAttn 融合多模态令牌与上一状态，实现逐查询递归更新；池化摘要 `W̄k` 用于事件检索。
4. **稀疏事件记忆（Sparse Event Memory）**：容量 16，事件体含视觉特征、阶段信息、时间特征及检索键；使用年龄感知的余弦相似度评分选择锚点与最高分记录，经 CrossAttention 融合为读出令牌 `Zek`。有阶段标注时用阶段转移触发写入；无标注时按每 3 个查询定期写入。
5. **Motion Tail 两条模型侧通路**：
   - 尾部令牌（tail tokens）输入工作状态构建；
   - 对齐后的轨迹均值作为动作生成初始化：`A~(0)|uk+1 ~ N(μk+1, σ²u I)`（带噪声的条件初始化）。
6. **训练目标**：条件流动作目标 + 阶段监督（有标注时）+ 重叠一致性正则（overlap-consistency regularizer，权重 0.2）。训练时以 0.5 概率使用前驱的 detached 尾部，否则屏蔽尾部通路。

## 3. 实验设计

- **主基准 RMBench（记忆依赖操控）**：5 个任务（Obs. Rearr.、Rearrange Blocks、Put Back Block、Swap Blocks、Swap T.），每任务 100 个 rollout 回合，每任务一个适配模型，是主要的诊断设置。对比方法含 DP、ACT、π0.5、X-VLA、MemER、MemoryVLA、Mem-0、MemoAct、PAM、Goal2Skill 等。
- **广度基准 LIBERO**：Spatial、Object、Goal、Long 四个套件，每套件微调一个模型，每任务 50 回合。对比方法含 OpenVLA、SpatialVLA、π0-FAST、GR00T-N1、π0、π0.5+KI（+ Kalman Initializer，表内为 π0.5+KI）、PAM、MemoryVLA、CronusVLA、X-VLA 等。
- **内部对照统一协议**：Florence-2-large 骨干 + 条件流解码器，每任务 50 条演示、20,000 步优化、batch size 4；所有变体都能单独访问已执行动作历史，以区分"去除携带状态"而非"失去动作历史"。
- **消融实验（RMBench）**：逐步移除 Progress Context 各部件（阶段标注、直播令牌、事件读出、整体）、Motion Tail 各部件（尾令牌、轨迹初始化、整体）、以及同时去除两者，另设替代对照组（FIFO 观测历史 + Temporal Ensemble）。
- **边界诊断**：在匹配场景下配对 Full 与 w/o Motion Tail 的 rollout（Put Back 20 对、Rearrange 30 对、Swap Blocks 30 对），测量位置/姿态指令不连续（CDp、CDR）、边界二阶差分（B2）、三步重叠 RMSE（RMSE3）。
- **后解码平滑对照**：Linear Continuation、Temporal Ensemble 仅做执行侧平滑而不做模型侧条件化。

**主要结果：**
- RMBench：Full 平均 **62.8%**，优于完整五任务覆盖的最佳基线 Mem-0（52.8%，8B+2B 参数）；Put Back Block 96% vs Mem-0 90%。
- LIBERO：平均 **98.8%**（98.4 / 99.4 / 99.2 / 98.2），Long 套件 98.2%。
- 消融：w/o Motion Tail 11.2%；w/o Progress Ctx. 3.0%；w/o Both 1.6%；FIFO Hist. + TE 35.6%；部分移除按预期插值（w/o Live Tokens 47.2、w/o Event Readout 32.2、w/o Tail Tokens 52.0、w/o Traj. Init. 38.0）。
- 平滑对照：Linear Continuation 边界指标更低但成功率 0–2%；Temporal Ensemble 成功率 0%。

## 6. 主要结论与发现

- **跨查询链式状态显著提升长时程表现**：完整模型 RMBench 62.8%（1.2B 参数）优于更大的记忆增强基线。
- **两个状态组件缺一不可且高度非独立**：单独保留任一组件（11.2% 或 3.0%）远低于完整模型，且两半相加远不等于 62.8%，说明二者是连续协作而非并行能力。
- **运动延续通过保护观测流来支持任务进展推断**：去掉 Motion Tail 后边界指令不连续显著增大（位置 CD 池化降低 56.6%、B2 降低 57.4%、RMSE3 降低 43.1%），恢复性重规划使手臂访问与演示不一致的视点，从而破坏任务进展的写入与检索——这是不对称消融的关键解释。
- **仅平滑输出无法替代模型侧条件化**：Linear Continuation/Temporal Ensemble 边界指标不差甚至更低，但成功率几乎为 0，说明"何时使用后缀"（生成前条件化）比"是否使用后缀"（生成后平滑）更关键。

- **问题识别清晰**：将跨查询交接明确拆分为"任务进展"与"未完成运动"两个互补维度，并以决策不充分性做形式化刻画，提供了统一视角。

## 7. 优点（续）

- **机制设计巧妙（续）**：Motion Tail 以"可修订先验"而非"固定计划"进入解码器，既保留了未执行动作的连贯性，又允许最新观测将其覆盖。这一设计在概念上介于"硬约束"与"完全自由生成"之间，兼顾了平滑性与响应性。
- **训练与部署的一致性设计**：查询转移公式在训练和推理时共享同一有序转移（`uk` 的传递路径一致，训练时仅对尾部做 detach），避免了常见的"训练-推理不一致"问题；0.5 概率随机屏蔽尾部通路的做法也可视为一种正则化，使模型在有无运动先验两种情形下都能正常工作。
- **消融设计具有解释力**：作者不仅做了组件移除，还构造了"仅移除携带状态但保留动作历史可得性"的对照（所有变体都能访问已执行动作历史），从而把性能差异归因于"携带状态的表示方式"而非"信息是否可得"。配合边界配对实验，给出了不对称消融（去 Motion Tail 损失更大）的机制解释，而非停留在现象层面。
- **写作与可复现性**：问题形式化、数学符号、算法流程清楚；训练超参数、硬件、数据规模均有交代；对基线比较的局限（外部基线未统一重跑）有明确的自我声明，学术态度坦诚。

## 8. 局限与局限的潜在反驳

- **单一种子、无显著性检验**：全文内部实验均为单种子点估计，20,000 步训练在长时程任务上存在不小的方差风险。但是，文中主要结论的效应量极大（例如 62.8% vs 11.2% vs 3.0%），远超一般的随机波动范围，因此核心定论不太可能被种子翻转；真正的风险在于幅度较小的中间差值（如 52.0 vs 38.0 的插值关系）可能不够稳健。
- **RMBench 外部基线参数规模不齐**：对比的 Mem-0 是 8B+2B 参数模型，ChainVLA 仅 1.2B，这反而衬托了本方法的效率；但反过来，更强的基线在更大尺度上可能尚未被充分调优。作者承认基线结果从原文引用，未统一协议重跑，这在 VLA 评测中属于常态，但也意味着主表对比的公平性只能视为"参考性"，不能视为"严格受控比较"。
- **场景覆盖有限**：RMBench 的 5 个任务虽被设计为"记忆依赖"，但排列/取放类操作在感知-动作耦合上仍属中等复杂度；LIBERO 任务则已近天花板，区分度不足。作者并没有在人形/灵巧手/多机协同等更复杂的操控形态上验证链式状态的可扩展性。
- **"进展"的定义与工作状态的可解释性不足**：虽然形式化给出了 `gk` 的更新规则，但工作状态是 8 个学习查询的隐向量，事件记忆中的"阶段信息"依赖标签或启发式触发（每 3 个查询）。实际中学到的"任务进展"是否语义上对齐人类的阶段划分，文中没有可视化或探针分析。
- **记忆容量与写入策略的敏感性未充分探索**：容量 16、每 3 个查询写入一次的设置看似合理但缺乏敏感性分析（如容量 8、32 会怎样？写入频率 1/5/10 查询会怎样？）。对于长时程任务的扩展性（几百步任务）仍属未知。

## 9. 我的质疑

- **为什么不对称消融的效应如此之大？** w/o Progress Context（3.0%）几乎坍缩为随机水平，而 w/o Motion Tail（11.2%）也很低。作者的解释是：无运动尾部时，模型"过度响应"当前观测，频繁恢复性重规划导致工作状态和事件记忆被污染。这个解释合理，但它高度依赖"状态写入完全由观测驱动"这一设计选择。如果写入策略对观测视角变化更鲁棒（例如在固定帧中记录物体位姿而非仅视觉特征），去除 Motion Tail 的伤害是否会被极大缓解？反过来，也说明 Progress Context 的表示方式可能过度耦合于当下视角，而非真正解耦的任务状态。
- **轨迹初始化后解码器是否真的"重新生成"了每一个位置？** 论文称每个位置都在新观测下重新生成，但条件是 `N(μ, σ²I)` 的高斯初始化。若 σ 太小，解码器可能难以偏离先验，结果接近"复制尾部"而非"修订尾部"；若 σ 太大，又退化为无初始化。文中未给出 σ 的设置及敏感性实验，这一关键超参数决定了"可修订性"的实际程度。
- **重叠一致性正则化（权重 0.2）究竟在约束什么？** 它要求相邻查询重叠的时间步动作尽量一致，但这与"对新观测响应"之间存在张力——如果环境状态在新查询中已发生显著变化，一致性强约束反而会压制正确的反应。作者没有讨论该正则化对响应性的负面影响，也没有提供去掉正则化后的性能数据。
- **"严格前缀执行"与"每次查询预测 H 步"的设定是否是最优的？** 当前设定中每次规划窗口是固定 H，执行步数是固定 `hexec`。若采用自适应执行长度（如置信度触发提前结束），链式状态的收益是否会改变？文中未作这种变体实验，使得"固定滚动时域"这一设计选择是否必要、是否最优无法判断。
- **事件记忆的阶段标签从何而来？** 有标注时用阶段转移触发写入，无标注时退化为周期写入。但阶段标注是环境自动提供的还是人工标定的？若需人工标注，则方法声称的"无标注可用"仅体现在退化的周期写入上，此时性能差异（文中未单独报"无阶段标注"的完整模型）并不清楚。这直接影响方法在真实部署中的可用性声明。

## 10. 启发与展望

- **"交接状态"应视为 VLA 的一等公民**：ChainVLA 的贡献不在于引入某种新的骨干或动作解码器，而在于改变了策略的"跨查询记忆接口"。这提示后续工作可以不必改动大规模预训练骨干，仅在策略外壳上增加状态传递机制即可获得大幅提升——这对于参数受限的机器人部署场景尤其有吸引力。
- **任务进展与运动延续的分离具有普遍意义**：这一二维分解（回顾性进展 + 前瞻性动作尾巴）不仅适用于"滚动时域执行"，也可能适用于其他需要连续决策的序列化架构（如扩散策略的迭代细化、分层规划中的跨层传递）。
- **可修订先验的思想可以推广**：把上一次预测当作"条件初始化"而非"必须执行的计划"，这一思路天然契合扩散/流匹配解码器的迭代精炼机制。未来可以探索"多候选尾部选择"、"基于置信度的尾部衰减"或"对尾部施加层级化修订权重"等扩展。
- **边界指标（CD、B2、RMSE3）是值得推广的评测工具**：当前 VLA 研究普遍只报成功率，ChainVLA 给出了量化跨查询不连续性的诊断指标，能区分"结果好"与"行为连续"两个维度。这套指标可复用于长时程、多阶段操控的评测。
- **无标注设定下的记忆触发**：事件记忆的阶段感知写入依赖标注，若能在无标注情形下用"工作状态转移的自发检测"来触发写入，将提升方法的通用性；这也是一个清晰的后续方向。

## 11. 总结与意义

ChainVLA 以一个简洁有力的观点贯穿全文：**长时程 VLA 策略在滚动时域执行下的失败根源，不是"记忆容量不够"或"动作不够平滑"，而是缺少一种同时编码"任务进展"与"未完成运动"的、跨查询可修订的交接状态。** 作者用 1.2B 参数的策略，在 RMBench 上超过 8B+2B 的记忆增强基线，并将 LIBERO 推至近天花板水平；更重要的是，消融与边界诊断揭示了两个状态组件之间深刻的互补关系——运动延续通过保护观测流来维持事件记忆的可靠性，而任务进展为运动延续提供了语义上下文。这一"链式状态"设计为后续长时程操控策略提供了一种轻量、通用且具有明确理论动机的改进范式。
