## 摘要
技能已成为使大型语言模型（LLM）智能体在长期交互任务中复用过往经验的重要抽象。然而，现有的轨迹到技能方法通常产生扁平化的高级文本技能集合，这些技能被独立存储和检索，导致技能间关系未被充分利用，并在高级技能与可执行动作之间存在差距。本文提出HiSkill，一种分层技能图框架，将交互轨迹组织为包含技能节点、原子操作节点和类型化边的有向图。具体而言，该图将可复用的高级技能与可执行动作模板相连，同时捕获它们之间的分解、时间转换、兼容性、支持及恢复关系。在推理时，HiSkill检索紧凑的任务相关子图，并执行子图引导的任务执行，其中符号任务状态、活跃技能和检索到的子图引导LLM智能体迭代地切换技能、选择原子操作并落地可执行动作。在三个交互环境上的实验表明，HiSkill在降低推理令牌消耗的同时优于最先进的基线方法，证明了通过分层技能图连接高级技能与可执行动作落地的有效性。我们的数据和代码可在 https://github.com/BUPT-GAMMA/HiSkill 获取。

## Abstract
Skills have become an important abstraction for enabling large language model (LLM) agents to reuse past experience in long-horizon interactive tasks. However, existing trajectory-to-skill methods often produce flat collections of high-level textual skills that are stored and retrieved independently, leaving skill relations underutilized and maintaining a gap between high-level skills and executable actions. In this paper, we propose HiSkill, a hierarchical skill graph framework that organizes interaction trajectories into a directed graph with skill nodes, AtomicOp nodes, and typed edges. Specifically, the graph connects reusable high-level skills with executable action templates, while also capturing decomposition, temporal transition, compatibility, support, and recovery relations among them. At inference time, HiSkill retrieves a compact task-relevant subgraph and performs subgraph-guided task execution, where a symbolic task state, an active skill, and the retrieved subgraph guide the LLM agent to switch skills, select AtomicOps, and ground executable actions iteratively. Experiments on three interactive environments show that HiSkill outperforms state-of-the-art baselines while reducing inference token consumption, demonstrating the effectiveness of bridging high-level skills and executable action grounding through a hierarchical skill graph. Our data and code is available at https://github.com/BUPT-GAMMA/HiSkill.

## 1. 核心问题与整体含义

- **研究背景**：长程交互任务要求 LLM 智能体在连续多步交互中解决问题，复用历史经验是关键。技能（Skill）作为一种可复用的过程性知识单元，是组织经验的重要抽象；但目前从轨迹自动提取技能的方法通常把技能组织成**扁平的、高层文本描述集合**，独立存储和检索。
- **两大局限**：
  1. **高层技能与可执行动作之间存在鸿沟**：技能多为粗粒度策略或文本指导，难以直接决定下一步具体动作（含参数和时机）。
  2. **技能间关系未被充分利用**：许多过程步骤跨任务共享，但现有方法按独立单元构建和检索，忽略了技能间的分解、时序、兼容、支持、恢复等执行关系。
- **整体含义**：HiSkill 提出用**层次技能图**统一组织高层技能、可执行动作模板及其关系，从而既保留可复用的过程知识，又能把技能落地为具体动作，实现更高效、更稳定的交互决策。

## 2. 方法论

### 2.1 核心思想

将历史交互轨迹转换为一个有向图，图中包含两类节点、五类有向边，形成“技能—动作”分层结构；推理时检索任务相关子图，并用符号状态和 LLM 引导逐步执行。

### 2.2 关键技术细节

- **分层技能图构造**：
  - 将轨迹划分为成功轨迹 $T^+$ 与失败轨迹 $T^-$，分别用于提取可复用模式和恢复证据。
  - **原子操作提取**：用基于模板的 canonicalizer 将原始动作规范化为动作模板，并用占位符替换任务特定实体，形成 AtomicOp 节点集合 $V_O$。
  - **技能发现**：从成功轨迹的 AtomicOp 序列中挖掘频繁动作模式，抽象为技能节点 $V_S$；每个技能保存有序 AtomicOp 序列和结构化元数据（适用状态、预期状态变化、示例、参数候选、支持计数、失败提示）。
  - **类型化边归纳**：边类型 $\mathcal{L}=\{decomposes\ to,\ can\ follow,\ compatible\ with,\ supports,\ recovers\ with\}$，分别由轨迹统计、状态兼容性、失败模式与语义匹配归纳。例如成功轨迹主要诱导分解、时序、兼容、支持关系，失败轨迹主要诱导恢复关系。

- **任务相关子图检索**：
  - 将任务描述与初始观察拼接为查询，对每个节点计算混合相关性分数：
    $$\text{score}(v|q)=\lambda\,\text{Dense}(x_q,d_v)+(1-\lambda)\,\text{Sparse}(x_q,d_v)$$
    其中 Dense 为嵌入余弦相似度，Sparse 为 BM25 分数。
  - 分别对技能节点和 AtomicOp 节点排序，取 top-K 作为种子节点。
  - 进行图扩张（Graph Hydration）：对 `decomposes to` 边保留后继 AtomicOp；对其他类型边做一跳邻居扩展，最终形成紧凑子图 $G_q$。

- **子图引导的任务执行**：
  - 维护**符号任务状态** $z_t$（键值记忆）和**活跃技能节点** $s_t$。
  - **技能切换**：初始技能由 LLM 从候选技能中挑选；当技能完成后通过 `can follow` / `compatible with` 切换后继技能；当执行卡住或重复失败时通过 `recovers with` 切换到恢复技能。
  - **原子操作选择**：默认选择活跃技能中下一个未执行的 AtomicOp；缺少前置条件时通过 `supports` 选择支持操作；失败时通过 `recovers with` 选择恢复操作；若均不合适，允许 LLM 直接生成动作。
  - **动作落地与状态更新**：将选中的 AtomicOp 模板按当前观察和状态实例化，生成可执行动作 $a_t$，执行后更新状态：
    $$z_{t+1}=\text{UpdateState}(z_t,a_t,o_{t+1})$$
    如此迭代直到任务完成。

## 6. 主要结论与发现

- HiSkill 在三个环境的 Seen/Unseen 基准上均优于最强基线：在 Gemini-2.5-Pro 下平均相对提升 17.33%（成功率）、22.95%（分数）；在 GPT-5.2-Codex 下平均相对提升 11.91%（成功率）、18.31%（分数）。
- **推理 token 消耗显著降低**：相比最省 token 的基线，ALFWorld、WebShop、ScienceWorld 上分别减少约 61.10%、94.12%、66.76%，表明性能提升来自紧凑的结构化技能图而非长上下文。
- 消融表明：AtomicOp 节点、类型化边、支持/恢复边和动态任务状态均对最终性能有贡献；直接使用静态子图或仅注入 top-K 技能文本效果较差，说明**检索子图需要与动态执行机制结合**。
- 图表示与执行机制应联合设计：组件迁移实验（OurG+GoSUse、GoSG+OurUse）均弱于完整方法，说明单独替换表示或使用方式都不足以发挥最大效益。
- 超参数分析显示：λ 取中间值（约 0.5～0.75）优于纯语义或纯词汇检索，K=6 是种子节点预算的良好折中。

## 7. 优点

- **方法论上**：将技能从“文本提示”提升为“可执行过程抽象”，用层次图显式连接“技能—动作”并建模五种执行关系，填补了高层技能与动作落地的空白。
- **推理机制**：结合符号任务状态与图引导，使技能切换、原子操作选择和动作实例化具有明确依据，降低了 LLM 自由发挥的不确定性。
- **兼顾效率**：通过子图检索和紧凑图结构，在提升性能的同时大幅降低 token 消耗，实际部署成本更低。

## 8. 不足与局限

- **环境局限**：实验仅在文本交互环境（ALFWorld、WebShop、ScienceWorld）中进行，未涉及视觉/物理仿真或真实世界交互，结论外推需谨慎。
